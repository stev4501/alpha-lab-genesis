# Day-1 Autonomous Stock-Strategy Research Agent — Source Evaluation and Core-Skill Recommendation

Session date: 2026-08-05. All values below were fetched in this session from the linked URLs (GitHub REST API records, repository READMEs, and project documentation). `n.a.` means the value could not be confirmed from a fetched page.

Design frame used for classification:
- **Immutable core** — a pattern/skill the agent must never rewrite, because it is what makes evidence falsifiable (evaluation, preregistration, memory, session bounds).
- **Optional specialist skill** — loaded on demand for a class of experiments.
- **Tool/library dependency** — executable infrastructure the agent calls but does not author.
- **Reject** — do not adopt as a dependency (harvest ideas only, or skip).

| Field | Finding |

| Maintained status | Last push `2026-03-26T00:07:37Z`, not archived, 93,123 stars per the [GitHub API repo record](https://api.github.com/repos/karpathy/autoresearch); latest commit on `master` is [`228791fb` "Merge pull request #342 from kaizen-38/feat/bug-fix"](https://github.com/karpathy/autoresearch/commit/228791fb499afffb54b46200aca536f79142f117) dated `2026-03-26T00:07:37Z` per the [commits API](https://api.github.com/repos/karpathy/autoresearch/commits?sha=master&per_page=1). License stated as MIT in the [README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md). |
| Core capability | A minimal harness for an agent to run autonomous overnight research on a single-GPU LLM training task: "give an AI agent a small but real LLM training setup and let it experiment autonomously overnight… modifies the code, trains for 5 minutes, checks if the result improved, keeps or discards, and repeats" ([README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md)). |
| Pattern worth translating | Four transferable patterns, all from primary text. (a) **Fixed budget for comparability**: "training runs for a **fixed 5-minute time budget**… this makes experiments directly comparable regardless of what the agent changes (model size, batch size, architecture, etc)" ([README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md)). (b) **Immutable evaluator**: `prepare.py` "is read-only… The `evaluate_bpb` function in `prepare.py` is the ground truth metric", and the agent "CANNOT modify the evaluation harness" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)). (c) **Append-only decision ledger**: a 5-column TSV `commit / val_bpb / memory_gb / status / description` with `status: keep, discard, or crash` ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)). (d) **Branch-per-run with advance-on-improvement**: "If val_bpb improved (lower), you 'advance' the branch… If val_bpb is equal or worse, you git reset back to where you started", on a dedicated branch `autoresearch/<tag>` that "must not already exist — this is a fresh run" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)). The README also frames the instruction file itself as a skill: "The `program.md` file is essentially a super lightweight 'skill'" ([README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md)). |
| Classification | **Immutable core** — as a pattern source, not a dependency. Fixed-budget harness + sealed evaluator + keep/discard ledger becomes the agent's experiment spine. |
| Integration risks | (1) The loop is greedy single-run hill-climbing on one metric with no significance test; in finance that is textbook backtest overfitting, so the accept rule must be replaced with a purged/out-of-sample + trial-count-aware rule. (2) `program.md` instructs "do not commit the results.tsv file, leave it untracked by git" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)) — the opposite of durable append-only memory; must be inverted. (3) "**NEVER STOP**… do NOT pause to ask the human if you should continue" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)) directly conflicts with bounded sessions and must be replaced by a session budget + clean handoff. (4) No notion of data leakage, point-in-time data, or portfolio accounting exists anywhere in the harness. |
| Rationale | Highest-value non-financial source: it is the cleanest published statement of "make experiments comparable by fixing the budget and sealing the scorer", which is precisely the missing discipline in agentic strategy search. |

| Rationale | Qlib supplies the two hardest Day-1 primitives in first-party prose: a concrete point-in-time storage/query design and a declarative, diffable experiment specification that doubles as a preregistration record. |

## 3. Ranked recommendation: 7 additional Day-1 core skills

Ranking criterion: how much falsifiability is lost if the skill is absent on Day 1. Skills 1–4 are non-negotiable; 5–7 are core but can be thinner on Day 1.

### #1 — `preregister-experiment` (highest priority)

- **Scope.** Convert an idea into a frozen, machine-readable hypothesis record *before* any data is touched: hypothesis statement, economic rationale, universe, sample windows (train/validation/holdout), data vintage id, primary metric and its direction, secondary metrics, decision thresholds, cost/execution assumptions, seed(s), planned number of parameter trials, and the pass/fail rule. Also debits the trial budget.
- **Trigger.** Any intent to run an experiment, sweep, fit, or backtest. Hard gate: the experiment runner refuses to execute without a valid preregistration id.
- **Required inputs.** Hypothesis text; universe definition; date segments; metric name/direction/threshold; data vintage id from `pit-data-contract`; execution-assumption block; trial budget request; agent/session id.
- **Outputs.** One append-only record (`prereg/<id>.yaml` + a line in `ledger/hypotheses.jsonl`), hash-committed; the id is stamped on every downstream artifact.
- **Invariants.** (i) Immutable once written — amendments are new records that reference the parent, never edits. (ii) Metric, thresholds and segments cannot change after first execution; a changed metric forces a new preregistration and a fresh trial debit. (iii) No holdout window may appear in any preregistration more than N times (N declared in core config). (iv) Every reported number must resolve to exactly one preregistration id.
- **Sources.** Qlib's single-YAML declaration of segments, model hyperparameters, and backtest costs ([Workflow Management](https://qlib.readthedocs.io/en/latest/component/workflow.html)); autoresearch's fixed-metric contract and per-run branch tag ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)); MLflow's params/notes/tags as searchable run metadata including `mlflow.note.content` ([MLflow Tracking docs](https://mlflow.org/docs/latest/ml/tracking/)); RD-Agent's explicit hypothesis→experiment-design→implementation→feedback sequence ([repository overview](https://github.com/microsoft/RD-Agent)).

### #2 — `pit-data-contract` (point-in-time integrity and as-of access)

- **Scope.** All data access goes through an as-of interface. Every dataset gets a vintage: source, retrieval timestamp, coverage window, row count, content hash, revision policy, and known restatement behavior. Handles universe membership (survivorship), corporate actions/adjustment basis, and publication lag for fundamentals.
- **Trigger.** Any read of market, fundamental, or alternative data; any dataset refresh; any new source registration.
- **Required inputs.** Source adapter id; requested symbols/universe; `as_of` timestamp; field list; adjustment basis; expected publication lag.
- **Outputs.** An immutable vintage manifest (`data/vintages/<vintage_id>.json` with hashes), a read-only snapshot or catalog reference, and a leakage report (fields whose availability timestamp is later than the requested `as_of`).
- **Invariants.** (i) No query may return a value whose publication date exceeds the requested `as_of` — Qlib's rule: for a signal on 1 January 2020, only 1 January 2020 and earlier data are available ([PIT docs](https://qlib.readthedocs.io/en/latest/advanced/PIT.html)). (ii) Restated/amended values must be stored as new versions, never overwritten (the `date`/`period`/`value`/`_next` revision-chain shape). (iii) Universe membership is resolved as-of, not from today's index constituents. (iv) A vintage hash mismatch invalidates every dependent result. (v) Backtest and paper-execution paths must read the same adapter, so that "online-trading behavior and historical-backtesting behavior" stay the same ([PIT docs](https://qlib.readthedocs.io/en/latest/advanced/PIT.html)).
- **Sources.** Qlib PIT database design and stated motivation ([PIT docs](https://qlib.readthedocs.io/en/latest/advanced/PIT.html)); zipline-reloaded's `zipline ingest -b <bundle>` plus `--bundle-timestamp` ("The date to look up data on or before") ([tutorial](https://zipline.ml4trading.io/beginner-tutorial.html)); Lean's raw-data-normalization split adjustment of live limit/stop/trigger orders as evidence that corporate actions must be modeled explicitly ([paper trading docs](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)); MLflow dataset linkage via `mlflow.log_input()` / `dataset=` ([MLflow Tracking docs](https://mlflow.org/docs/latest/ml/tracking/)).

### #3 — `leakage-and-overfitting-guard`

- **Scope.** Owns the validation protocol: purged + embargoed cross-validation or walk-forward, multiple-testing accounting across the whole session history, holdout sealing, and reporting distributions rather than point estimates.
- **Trigger.** Every fit, tune, sweep, or model-selection step; every promotion of a candidate from screening to holdout.
- **Required inputs.** Preregistration id; label horizon (to size purging); serial-correlation assumption (to size the embargo); fold configuration; cumulative trial count from the ledger; feature availability timestamps from `pit-data-contract`.
- **Outputs.** Fold/path definitions (persisted, so they are re-derivable), per-path metric distribution, a leakage assertion report, an updated trial-budget balance, and a promote/park/reject decision with reason.
- **Invariants.** (i) `purged_size > 0` and `embargo_size > 0` are mandatory — the library defaults `purged_size=0`, `embargo_size=0` are rejected ([CombinatorialPurgedCV API docs](https://skfolio.org/generated/skfolio.model_selection.CombinatorialPurgedCV.html)). (ii) `purged_size` ≥ label horizon, because purging "Removes from the training set all observations whose labels overlapped in time with labels included in the testing set" ([API docs](https://skfolio.org/generated/skfolio.model_selection.CombinatorialPurgedCV.html)). (iii) Results are reported as a distribution across multiple recombined test paths, not one curve ([API docs](https://skfolio.org/generated/skfolio.model_selection.CombinatorialPurgedCV.html)). (iv) Every evaluated parameter combination debits the trial budget — a direct answer to vectorbt-style brute-force sweeps over `fast_window`/`slow_window`/`split_idx`/`symbol` grids ([vectorbt.dev](https://vectorbt.dev/)). (v) The sealed holdout is touched at most once per hypothesis. (vi) Report mean ± dispersion across seeds, as RD-Agent does (`30.22 ± 1.5`, 6 seeds) ([repository overview](https://github.com/microsoft/RD-Agent)).
- **Sources.** skfolio `CombinatorialPurgedCV` semantics and parameters ([API docs](https://skfolio.org/generated/skfolio.model_selection.CombinatorialPurgedCV.html)) and its Walk Forward / Multiple Randomized CV tooling ([skfolio.org](https://skfolio.org/)); mlfinlab's naming of "Cross-Validation" and "Backtest Overfitting Tools" as first-class pipeline modules ([README](https://raw.githubusercontent.com/hudson-and-thames/mlfinlab/master/README.md)); FinRL's train-test-trade stage separation ([README](https://raw.githubusercontent.com/AI4Finance-Foundation/FinRL/master/README.md)); MLflow child-run-per-fold ([MLflow Tracking docs](https://mlflow.org/docs/latest/ml/tracking/)).

### #4 — `sealed-evaluator-harness` (fixed-budget, comparable experiment execution)

- **Scope.** A single entry point that runs a preregistered experiment under a fixed, declared envelope (universe, calendar, frequency, capital base, cost/fill model, wall-clock and compute budget) and emits a standardized result record. The evaluator module is read-only to the agent.
- **Trigger.** A validated preregistration exists and inputs are resolved to a data vintage.
- **Required inputs.** Preregistration id; vintage id; strategy code reference (git commit); execution-assumption block; budget (wall clock and/or bar count); seeds.
- **Outputs.** A standardized result row keyed by *all* experiment coordinates (hypothesis id, param values, symbol/universe, split index, seed, vintage, code commit) plus artifacts (positions, trades, equity path) and a `keep / discard / crash` status.
- **Invariants.** (i) The scoring code is immutable within a core generation — autoresearch's rule that the evaluation harness cannot be modified and `evaluate_bpb` "is the ground truth metric" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)). (ii) The budget is fixed so results stay comparable across structurally different candidates ("this makes experiments directly comparable regardless of what the agent changes", [README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md)); a run exceeding the hard limit is killed and logged as a failure, mirroring "If a run exceeds 10 minutes, kill it and treat it as a failure" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)). (iii) Result rows must carry every coordinate — the vectorbt column-level discipline (`fast_window`, `slow_window`, `split_idx`, `symbol`) ([vectorbt.dev](https://vectorbt.dev/)). (iv) Crashes are recorded, never silently retried away (`status: keep, discard, or crash`) ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)). (v) Prefer the config-object/catalog tier of any engine so runs are serializable and replayable (`BacktestNode` "config objects, data catalogs, and batch runs") ([Nautilus backtesting concepts](https://nautilustrader.io/docs/latest/concepts/backtesting)).
- **Sources.** autoresearch fixed-budget + read-only evaluator ([README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md), [program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)); qlib `qrun` single-execution model with standardized `SignalRecord`/`PortAnaRecord` outputs ([Workflow Management](https://qlib.readthedocs.io/en/latest/component/workflow.html)); zipline-reloaded's explicit envelope flags `--data-frequency`, `--capital-base`, `--trading-calendar` ([tutorial](https://zipline.ml4trading.io/beginner-tutorial.html)); Nautilus two-tier API ([backtesting concepts](https://nautilustrader.io/docs/latest/concepts/backtesting)); vectorbt result keying ([vectorbt.dev](https://vectorbt.dev/)).

### #5 — `paper-execution-and-portfolio-ledger`

- **Scope.** Paper-only order lifecycle plus double-entry portfolio and risk accounting: orders → fills → positions → cash → NAV → risk measures, with declared fill/slippage/fee/margin models and enforced exposure limits.
- **Trigger.** Any candidate promoted to simulated trading or paper deployment; every session's mark-to-market of open paper positions.
- **Required inputs.** Target weights or orders; as-of prices from `pit-data-contract`; execution-assumption block (fill rule, slippage model, fee schedule, TIF, split handling, margin/buying-power model); prior ledger state; risk limits (gross/net exposure, per-name cap, drawdown stop, turnover cap).
- **Outputs.** Append-only order/fill/position/cash journal; NAV series; a risk report using preregistered measures; limit-breach events; a reconciliation record versus the corresponding backtest path.
- **Invariants.** (i) Paper only — no live-money credential is ever in scope; execution "Simulates order fills instead of routing orders to an exchange" ([Lean paper trading docs](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)). (ii) Zero-cost, zero-slippage runs are invalid as evidence: the `DefaultBrokerageModel` documents that orders "do not experience slippage in backtests or paper trading" ([Lean paper trading docs](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)), so the agent must override with an explicit cost model — e.g. equity fees of `$0.005 per share, with a $1 minimum` ([same page](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)) or qlib-style `open_cost: 0.0005 / close_cost: 0.0015 / min_cost: 5` ([Workflow Management](https://qlib.readthedocs.io/en/latest/component/workflow.html)). (iii) Buying power/margin must be modeled, not assumed ([Lean paper trading docs](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)). (iv) Simulation and paper paths share one execution and time model — divergence beyond tolerance is a defect ("The same execution semantics and time model apply in both backtests and live systems", [Nautilus docs home](https://nautilustrader.io/docs/latest/); "uses the same core system components as live trading… `Cache`, MessageBus, `Portfolio`", [backtesting concepts](https://nautilustrader.io/docs/latest/concepts/backtesting)). (v) The risk measure used for judgment is the preregistered one, chosen from a fixed menu (Variance, CVaR, EVaR, CDaR, EDaR, Maximum Drawdown, Ulcer Index, …) ([skfolio.org](https://skfolio.org/)). (vi) Turnover and transaction-cost constraints are declared up front ([skfolio.org](https://skfolio.org/)).
- **Sources.** Lean paper-trading brokerage model ([docs](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)); Nautilus parity and shared-component architecture ([docs home](https://nautilustrader.io/docs/latest/), [backtesting concepts](https://nautilustrader.io/docs/latest/concepts/backtesting)); zipline's commission/slippage/order-delay modeling ([tutorial](https://zipline.ml4trading.io/beginner-tutorial.html)); qlib backtest cost parameters ([Workflow Management](https://qlib.readthedocs.io/en/latest/component/workflow.html)); skfolio risk measures and cost/turnover constraints ([skfolio.org](https://skfolio.org/)).

### #6 — `bounded-session-protocol` with append-only memory + synthesis

- **Scope.** The wake/work/sleep contract: orient from memory, pick work by expected evidence gain, execute within budget, write results, synthesize memory, hand off. Includes the stop rule and the kill switch.
- **Trigger.** Every session start and every session end (both mandatory), plus budget-exhaustion interrupts.
- **Required inputs.** Session budget (wall clock, tokens, spend, max experiments); active memory files; open hypotheses and their states; trial-budget balance; prior session's handoff note.
- **Outputs.** A session plan; per-action ledger entries appended to `memory/*.jsonl`; regenerated active-context files; a handoff note naming the next session's first action; a session summary with spend and evidence delta.
- **Invariants.** (i) JSONL archives are the source of truth and are never rewritten or compressed — yoyo's `memory/learnings.jsonl … Append-only archives (source of truth, never compressed)` ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)). (ii) Prompt context is a *derived* artifact, regenerated by synthesis with "time-weighted compression (recent=full, old=themed)" ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)) — losing it must be recoverable from the archive. (iii) Sessions end cleanly and voluntarily: "If tests pass → commit. If not → revert. → Pushes and goes back to sleep" ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)). This explicitly overrides autoresearch's "**NEVER STOP**… do NOT pause to ask the human" instruction ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)), which is unsafe for a capital-adjacent agent. (iv) Recent outcomes are injected into planning, per `extract_trajectory.py Trajectory awareness — recent outcomes injected into planning` ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)). (v) State must be portable/restorable from the repository alone, in the spirit of GASP: "clone + fold to restore yoyo, on any runtime" ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)). (vi) Untracked result files are forbidden — the inverse of autoresearch's "do not commit the results.tsv file, leave it untracked by git" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)).
- **Sources.** yoyo-evolve session cadence, memory architecture, and trajectory tooling ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)); autoresearch loop mechanics and its anti-patterns to invert ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)); MLflow run start/end metadata and searchable history as the machine-side index ([MLflow Tracking docs](https://mlflow.org/docs/latest/ml/tracking/)).

### #7 — `skill-lifecycle-governance`

- **Scope.** How the agent creates, refines, retires, and versions its own skills, and what it may never touch. Maintains the immutable-core manifest and the promotion path from ad-hoc script → optional specialist skill → core.
- **Trigger.** Recurring procedure detected (same manual sequence ≥ k times); a skill fails repeatedly; a new specialist capability is needed; any proposed change to a core skill.
- **Required inputs.** Candidate skill spec (scope/trigger/inputs/outputs/invariants); evidence of repeated need from the ledger; test suite for the skill; current core manifest and its version.
- **Outputs.** A versioned skill file with frontmatter, tests, a changelog entry, an updated core manifest, and a ledger entry recording create/refine/retire with rationale.
- **Invariants.** (i) A named, small immutable core exists and is enumerated — yoyo ships `14 skills — 7 core (immutable)` and treats them as off-limits to self-evolution ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)); for this agent the core is preregistration, PIT data contract, leakage guard, sealed evaluator, paper/portfolio ledger, session protocol, and this governance skill. (ii) Core changes require a generation bump that invalidates cross-generation metric comparisons, because comparability is only guaranteed within a fixed harness ([autoresearch README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md)). (iii) Every skill change is tests-gated with commit-or-revert ([yoyo README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)); for this agent the gate additionally asserts the invariants of skills #1–#5. (iv) Retirement is explicit and logged, following `skill_evolve.sh  Autonomous skill evolution (refine / create / retire its own skills)` ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)). (v) Instruction-only skills may be authored freely; changes to executable infrastructure in the sealed evaluator are prohibited within a generation ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)). (vi) Prefer simplicity: "All else being equal, simpler is better… A 0.001 val_bpb improvement from deleting code? Definitely keep" ([program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)); mirrored by RD-Agent(Q) reporting "over **70% fewer factors**" as a headline result ([repository overview](https://github.com/microsoft/RD-Agent)).
- **Sources.** yoyo-evolve immutable-core split, `skill_evolve.sh`, skills system with YAML frontmatter and install/search ([README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)); autoresearch's "`program.md` is essentially a super lightweight 'skill'" and its simplicity criterion ([README](https://raw.githubusercontent.com/karpathy/autoresearch/master/README.md), [program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md)); RD-Agent's Copilot-vs-Agent role distinction ([repository overview](https://github.com/microsoft/RD-Agent)).

## 4. Skill instructions vs. executable infrastructure

The distinction matters because instructions are cheap, editable, and model-dependent, while infrastructure is what actually makes cheating impossible. Where a guarantee must survive a persuasive-sounding LLM rationalization, it must live in code.

| Concern | Skill instructions (markdown, agent-editable outside core) | Executable infrastructure (code, sealed within a generation) |
|---|---|---|
| Preregistration | How to phrase a hypothesis, choose an economically motivated metric, size thresholds | Schema validator; append-only hash-chained `hypotheses.jsonl`; runner refuses execution without a valid id |
| Point-in-time data | How to reason about publication lag, restatements, survivorship | As-of query API, vintage manifests with content hashes, availability-timestamp assertions ([Qlib PIT design](https://qlib.readthedocs.io/en/latest/advanced/PIT.html)) |
| Leakage / overfitting | When to use walk-forward vs combinatorial paths; how to interpret a path distribution | CV splitter with enforced non-zero `purged_size`/`embargo_size`, trial-budget accountant, holdout seal ([skfolio API](https://skfolio.org/generated/skfolio.model_selection.CombinatorialPurgedCV.html)) |
| Comparability | How to design a fair comparison; what to hold constant | Fixed-budget runner, sealed scorer module, mandatory result-key schema ([autoresearch program.md](https://raw.githubusercontent.com/karpathy/autoresearch/master/program.md), [vectorbt.dev](https://vectorbt.dev/)) |
| Reproducibility | How to describe a run so a human can rerun it | Git-commit pinning, seed capture, MLflow run/artifact/dataset linkage, replayable config objects ([MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking/), [Nautilus BacktestNode](https://nautilustrader.io/docs/latest/concepts/backtesting)) |
| Portfolio / risk | Which risk measure suits which hypothesis | Double-entry position/cash journal, NAV series, limit enforcement, risk-measure library ([skfolio.org](https://skfolio.org/)) |
| Paper execution | How to choose realistic assumptions | Broker/fill/slippage/fee/margin model objects, order-lifecycle simulator, parity reconciliation test ([Lean paper trading](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)) |
| Session bounds | How to prioritize work; how to write a handoff | Budget timers, hard kill on overrun, session-open/close hooks that cannot be skipped ([yoyo README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)) |
| Memory | What is worth remembering; how to summarize | Append-only JSONL writer, daily synthesis job regenerating active context, restore-from-archive path ([yoyo README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)) |
| Skill lifecycle | When to create/retire a skill | Core manifest, generation versioning, test-gated commit-or-revert on skill changes ([yoyo README](https://raw.githubusercontent.com/yologdev/yoyo-evolve/main/README.md)) |

**Minimum Day-1 executable footprint** (deliberately small, all permissive licenses): Python + pandas/NumPy; `zipline-reloaded 3.1.1` ([release](https://github.com/stefan-jansen/zipline-reloaded/releases/tag/3.1.1), Apache-2.0) *or* a home-built daily-bar simulator behind the sealed evaluator; `skfolio v0.20.1` ([release](https://github.com/skfolio/skfolio/releases/tag/v0.20.1), BSD-3-Clause) for purged CV and risk measures; `mlflow v3.15.1` ([release](https://github.com/mlflow/mlflow/releases/tag/v3.15.1), Apache-2.0) as the run index behind a git-committed append-only ledger; `qlib v0.9.7` ([release](https://github.com/microsoft/qlib/releases/tag/v0.9.7), MIT) as the reference for the PIT store rather than a Day-1 runtime. Defer Lean, NautilusTrader, vectorbt (Commons Clause restriction, [LICENSE.md](https://raw.githubusercontent.com/polakowo/vectorbt/master/LICENSE.md)), FinRL, and RD-Agent to optional specialist skills. Do not depend on quantopian/zipline, backtrader, or mlfinlab.

**Framing guardrail.** Every source that reports strong performance does so as a self-report — e.g. RD-Agent(Q)'s "approximately **2× higher ARR**" claim on its own README ([repository overview](https://github.com/microsoft/RD-Agent)) and vectorbt's tutorial returns such as `1.721449` for a single parameter/split/symbol cell ([vectorbt.dev](https://vectorbt.dev/)). The Day-1 core exists to make the agent's own numbers harder to believe than these: distributions over purged paths, one sealed holdout touch, costs never zero, and a preregistration for every claim.
