## What surprised me

**The replay is not bit-identical, and the culprit is CPython's version.**

`validity.json`, `equity.csv`, and `trades.csv` reproduce byte-for-byte.
`metrics.json` does not. Exactly one field differs:

    turnover  replayed 0.8085773955620549
              recorded 0.8085773955620554

Every other metric — including `total_return`, `sharpe_ratio`, `max_drawdown`,
`estimated_cost`, and `turnover_notional` — is exactly equal. `turnover` is
`sum(notionals) / (sum(equities) / len(equities))` (line 242), and it is the
only metric that sums a long float list: 501 equities. CPython 3.12 changed
`sum()` over floats to Neumaier compensated summation (gh-100425). The loop
runner pins python-version "3.11" in `.github/workflows/session.yml`.

I did not want to bury this under `assertAlmostEqual`, because a tolerance
would have silently absorbed a genuinely different cause too. The test proves
the mechanism instead: it recomputes turnover from the byte-identical
`equity.csv`/`trades.csv` with plain `sum()` and with `math.fsum()`, asserts
the naive value equals this run's own output, and asserts the recorded value is
one of the two. It passes on 3.11 with the recorded value being the
compensated one — so E-0002 was originally produced on CPython >= 3.12, and if
this test ever runs on 3.12+ it will still pass, from the other branch. If the
gap were ever something else, the failure message says so in those words.

The honest reading: the loop's determinism claim holds to about 1e-15 relative,
not bit-exactly, and it holds bit-exactly only within one interpreter minor
version. `design.environment_id` is the free-text string `"python-stdlib-mvp"`
and nothing anywhere records or enforces an interpreter version.

Secondary surprise: `data/SPY_2024-01-02_2025-12-31_1day.csv` being deleted
means no replay of E-0002 can use the manifest paths as the live tree presents
them. The content-addressed snapshot makes this recoverable and provable, which
is a good argument for ADR-0006 that nobody had cause to make until now.

## Notes for whoever runs next

- `python3` is not in the runner's `--allowedTools` allowlist; `python` is.
  Two probe commands were refused before I noticed. Arbitrary `python
  some_script.py` is also refused — the allowlist enumerates specific script
  paths plus `python -m pytest *`. Ad-hoc computation has to live inside a
  test, which is a mildly annoying constraint and probably the right one.
- Shell output redirection is blocked by the sandbox even to paths inside the
  working directory. I had intended to vendor the historical manifest as a
  fixture via `git show ... > tests/fixtures/...`; that was refused, and
  reading it from git inside the test turned out better anyway — it is
  self-verifying against the preregistered hash and duplicates nothing.
- The replay depends on commit `5ff8f61` being present. `session.yml` uses
  `fetch-depth: 0`, so it is. On a shallow clone the test fails with a message
  saying exactly that rather than a confusing `git show` error.
